# Melodica Trainer — Handoff

A single-file, dependency-free web app for the owner's **Suzuki M-37C Plus** alto melodica (37 keys, F3–F6):
an on-screen keyboard drawn like the instrument, a **sampled sound recorded from that very melodica**, a coach
that lights the keys (with fingering) for any typed **progression, Roman-numeral pattern or melody**, a **chord
finder** with inversions, and **drills** with Leitner spacing and optional **microphone listening**.

- **Live:** https://melodica.terhunelabs.com (Cloudflare Pages project **`melodica-trainer`**, also `melodica-trainer.pages.dev`)
- **Repo:** https://github.com/jermn007/melodica-trainer · sibling of fretboard-trainer (same design system, theory, transport)
- **Spec:** `SPEC.md` (analysis, GUIDE learning design, technical spec, plan, decisions). Read it first.

## Run it
```
npm install        # jsdom for the smoke test only
npm run dev        # http://localhost:5174  (npx serve)
npm test           # headless jsdom smoke test: logic + rendering + drill engine + pitch detector (NOT layout/audio)
npm run build      # samples.mjs (recording/ -> samples/ MP3 + manifest) then build.mjs -> dist/
npm run deploy     # build, then wrangler pages deploy dist --project-name melodica-trainer
```

## Files
- `index.html` — the whole app: `<style>`, markup, one `<script>`.
- `recording/` — the owner's recorded note set: `53.wav`…`89.wav` (24-bit mono 44.1 kHz, trimmed to the attack,
  peak-normalised, a whole-period loop in the WAV `smpl` chunk, root note + INFO tags), `samples.json` (loop points,
  per-note gain, pitch check), `REPORT.md`. Source of truth for the sound. Recorded 2026-09-07.
- `samples/` — web encode of the above (96 kbps mono MP3 + `samples.json`), generated by `samples.mjs`; committed so
  a clone deploys without ffmpeg. ~500 KB.
- `tools/` — `make_session.py` (builds the guided REAPER recording session), `slice_samples.py` (take → note set),
  `make_icons.py` (favicon/icons/OG via Pillow), `RECORDING.md` (the owner's recording checklist).
- `build.mjs`, `samples.mjs`, `smoke-test.mjs`, `package.json`, `.claude/launch.json` (dev server for the Browser pane).
- Root assets `favicon.svg`, `icon-512.png`, `apple-touch-icon.png`, `og.png` ship at the site root (absolute URLs in `<head>`).

## Architecture (index.html)
- **Theory:** copied from fretboard-trainer (`NOTES/FLAT`, `SCALES` incl. blues with blue note, `DIA/ROMAN`, `CHORD_IV`
  + sus2/sus4, `usesFlats`, `diatonic`, `chordTones`, `parseChord`). Blue notes always spell flat.
- **Instrument:** `KB={lo:53,hi:89}` is the only instrument-specific constant; `LAY` maps each MIDI note to a white
  index / black flag. `REGISTERS` = Full / Low F3–F4 / Middle C4–C5 / High C5–F6.
- **State `S`:** `mode` (explore | chords | drill), `root`, `scale`, `labels` (all | landmarks | none), `names`
  (name | deg), `color` (role | pitch), `register`, `view` (auto | flat | held), `sound` (melodica | simple | off),
  `air`, `fingering`, `voicing` (smooth | root), `line` ({kind:'prog'|'melody', items}), `idx`, `chord`.
- **Keyboard SVG `buildKeys()`:** string template → `innerHTML`. Livery from the owner's photos: a red metallic
  body (`gRed`) whose top shows as the thin red rail (`gRail`, `G.rail`) and whose front shows as a sliver of red
  under a **chrome strip** along the key tips (`gSilver`, `G.lip`); blue end caps (`capPath`, `gBlue`, rounded
  outside, square against the black key bed); white highlight streaks (`gStreak`/`gStreakD`) give the sheet-metal
  sheen; keys use `gKey`/`gBlack` with a darker front lip on the whites. All gradients live in `DEFS` (object-space,
  so they rotate with the Held view). Then the `badge()` logotype, chrome mouthpiece ring, tube, 22 whites, 15 blacks;
  The **badge** ("m-37C Plus ≡ⓈSUZUKI≡") is a **vector trace of the real badge**: `tools/badge_crop.png` (the
  owner's photo crop, 383×49 px) → `tools/trace_badge.py` (whiteness score, unsharp mask, 6× upscale, Otsu + offset,
  marching squares, Douglas-Peucker; the oblique crop is mapped onto the panel's true 3.66:1 aspect) →
  `tools/badge_paths.json` (20 contours, ~530 points, IoU 0.95 against the mask) → `tools/build_badge.py` embeds it
  as `const BADGE` + `badge()` in index.html. Parameters used: `--sharpen 0.8 --level 0.08` (without them the tiny
  counters of the "s" in Plus and the "S" in SUZUKI fill in at this resolution). The panel is 150 units long beside
  the keys, rotated −90° so it reads bottom-to-top in Flat view and upright in Held view, as on the instrument.
  To re-trace from a sharper photo (a straight-on 1500 px crop would improve the small letters further): save the
  crop, run `python tools/trace_badge.py <crop> --out tools --sharpen 0.8 --level 0.08` then
  `python tools/build_badge.py`. No font is involved. Cap depths are `G.capL=86`, `G.capR=60` (≈51 mm and 35 mm of
  the 110 mm body depth, from the product photo). each key is `<g class="key" role="button"
  tabindex="0" data-midi>` with the face rect and overlays: register dim, next-chord dashed ring, chord-tone emerald
  ring, root/blue rings, the dot (label = note name or degree), fingering badge. `highlightFor(midi)` decides what a
  key shows this render. **Held view** = the flat drawing wrapped in `translate(H 0) rotate(90)` (low F at the top,
  red rail on the right, exactly the instrument seen from above); text counter-rotates. Auto = held in portrait.
  SVG presentation attributes use literal hex (`COL`, `PITCH`), never CSS vars.
- **Audio:** `ac()` builds ctx → in-gain → (dry + two LFO-modulated delays as a light chorus, wet .12) → low-pass +
  gain = **Air** (breath: 2–8 kHz, 0.5–0.7) → master. `loadSamples()` fetches `samples/samples.json` then all 37 MP3s
  on the first gesture. `voiceOn/voiceOff`: a looping `AudioBufferSourceNode` per held key (loopStart/End from the
  manifest, 8 ms attack, 160 ms release) or the sawtooth **synth fallback** while loading / offline / `Sound=Simple`.
  `play(midi,start,dur)` is the scheduled variant used by the transport. The metronome click bypasses Air.
- **Voicing engine:** `voicings(rootPC,qual)` enumerates every close-position inversion that fits F3–F6;
  `pickVoicing(list, prev)` chooses root position nearest the register centre (`Voicing=Root`) or the inversion with
  the least total semitone movement from the previous chord (`Smooth`, default); `fingeringFor` = RH numerals
  (triads 1-3-5 / 1-2-5 / 1-3-5, 7ths 1-2-3-5 / 1-2-4-5). `resolveLine()` assigns voicings to a whole progression once.
- **Coach (Explore):** `parseLine()` classifies the input as a progression (chord symbols, or Roman numerals with
  b/# and quality suffixes, resolved in the current key) or a melody (note names with optional octave, `-` holds,
  `.` rests, placed near the previous note inside the register); mixed lines report the unknown tokens. Diatonic
  chips append chords; Random uses the curated pools (12-bar blues when a blues scale is on). Transport steps chords
  every 2 beats and melody notes per beat on the **shared beat clock** with the metronome (ported from the
  fretboard); during playback the next chord ghosts with a dashed ring (`showNext`).
- **Chords mode:** `setChord()` → list of placements, `chooseChordVoicing()` by inversion + octave offset nearest the
  register centre, placements strip (`renderAlts`), readout "C · C E G · root".
- **Drill mode (`DR`):** `drillPool(type)` generates items from theory (12 note names; diatonic triads + V7/ii7/Imaj7;
  six curated progressions; six public-domain melodies in `MELODIES`, transposed to the key). `drawItems(10)` weights
  by Leitner box (`localStorage.mt_leitner`: box 0–3, misses → 0, hits → +1). Item types: **note** (press every
  instance; wrong keys count), **chord** (hold all tones at once, any inversion; 3 wrong attempts → shown),
  **prog** (2-beat count-in, then one chord per 2 beats with clicks; a step is matched if the held set equals the
  chord's pitch classes at any moment), **mel** (demo lights and plays the notes, then play back in order; 3 misses on
  one note reveal it). `onKeyInput(midi,down)` is the single input hook (screen, computer keyboard, mic). `Show me`
  reveals the answer and counts as a miss; `summary()` reports accuracy, per-type counts, median time, what's due.
- **Mic listening (`MIC`):** `getUserMedia` (no processing) → `AnalyserNode` 2048 → `pitchFromBuffer()`
  (autocorrelation; first peak ≥ 85 % of the best, so no octave errors) at animation rate; a pitch stable for 3
  frames fires `micNote()` once until the pitch changes or the signal drops below −40 dBFS. Feeds note and melody
  drills; chord drills stay on-screen. Needs HTTPS (Pages) or localhost.
- **Input:** pointer with capture (multi-touch chords), keyboard focus + Enter/Space, computer-keyboard piano map
  on `event.code` (Z–M = C4–B4, Q–U = C5–B5, `,`/`.` shift octave; typing in inputs is excluded).
- **Guide modal:** objectives, mode map, keyboard map, "Try this first" (`C G Am F` at 60 BPM). Shown once
  (`localStorage.mt_guide_seen`).

## Design constraints (preserve)
Single self-contained `index.html`, zero runtime deps, no CDN (only the Cloudflare Web Analytics beacon may be added);
dark theme tokens as in fretboard-trainer; SVG icons not emoji; 44 px targets; `:focus-visible` rings; every
animation gated by `prefers-reduced-motion`; colour never the only cue (labels/rings/aria); literal hex in SVG.

## Gotchas
- **`Samples/` vs `samples/`:** Windows is case-insensitive, so the WAV source folder is `recording/`. Don't rename.
- MP3 decoders prepend a constant offset; loop regions are whole periods well inside the steady part, so the seam
  survives the shift. If a note ever clicks, re-run the slicer (it reports `seam`; keep it < 0.25).
- `[hidden]{display:none!important}` exists because `.btn`/`.chip` set `display`, which would beat the attribute.
- `applyMode()` is the only place rows are shown/hidden; add new mode UI there.
- The instrument plays ~+10 cents sharp on average (real reeds); the samples are left untouched on purpose.
- Deploy: after `npm run deploy` check the live URL returns real HTML and `/samples/60.mp3` is `audio/mpeg`.
